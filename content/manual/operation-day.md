## 開場90分前

- [ ] 本番URLが表示されることを確認（スタッフ端末2台以上）
- [ ] 管理画面にログインできる
- [ ] 設置場所の一覧が意図どおり（公開／非公開、表示順）
- [ ] 係員暗証番号が「設定済み」になっている
- [ ] 新規参加登録が「受け付ける」になっている
- [ ] QR台紙を印刷し、予備を本部に確保した

## 開場60分前 — 掲示

- [ ] 各スポットにQRを掲示し、係員が1回ずつ読み取って確認
- [ ] 掲示位置が管理画面の「設置位置の案内」と一致している
- [ ] 入口の参加案内を設置した
- [ ] 特典交換場所と締め切り時刻を掲示した

> [!重要]
> 係員による確認の押印は、スタッフ自身の参加記録として残ります。ランキングを掲示する場合は、スタッフの記録を除外するか、事前に「スタッフは対象外」と掲示してください。

## 開催中（30〜60分ごと）

本部の当番が管理画面を見て、次を確認します。

| 見るところ | 正常 | 異常のサイン |
| --- | --- | --- |
| 参加者数 | 時間とともに増える | 30分以上増えない → 登録経路の障害 |
| 押印数 | 参加者数に比例して増える | 増えない → カメラかQRの問題 |
| コンプリート数 | 開始1〜2時間後から増える | 交換数との差が開く → 交換場所の案内不足 |
| 混み具合 | スポットごとに分散 | 1か所だけ「混雑」が続く → 導線の詰まり |

異常に気づいたら [トラブル対応](./troubleshooting.md) の順に切り分けます。**先に設定を変えないでください。** 公開中のスポットを動かすと達成条件が変わります。

## 終了30分前

- [ ] 「特典交換は◯時まで」を放送・掲示
- [ ] 未交換のコンプリート者数を管理画面で確認
- [ ] 報酬の残数を確認し、足りない場合の扱いを本部で決める

## 終了時刻

- [ ] 管理画面の「新規参加登録を受け付ける」を外す
- [ ] 交換の受付を締め切る（締め切り後は係員暗証番号を入力しない運用に切り替える）
- [ ] スポットのQR台紙を回収する（貼ったままにしない）

## 撤収後

- [ ] CSVを出力して保管（管理者のみ。[データ管理とCSV](./data-admin.md)）
- [ ] 発生した障害・手動対応をメモに残す
- [ ] 係員暗証番号を削除する
- [ ] データの削除日を決める（[個人情報の取り扱い](./privacy.md)）

片付けの全体は [開催後と次年度への引き継ぎ](./handover.md) に続きます。
