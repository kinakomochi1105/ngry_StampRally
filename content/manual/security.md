## 秘密情報の一覧

| 値 | 置き場所 | 変更の影響 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 環境変数 | 管理者セッションが全部切れる |
| `RALLY_SECRET` | 環境変数 | **既存QRと参加者Cookieが全部無効になる** |
| `TURSO_AUTH_TOKEN` | 環境変数 | 接続できなくなる |
| `NICKNAME_BLOCKLIST_KEY`・`NICKNAME_BLOCKLIST_IV` | 環境変数 | 値が合わないと新規登録ができなくなる |
| 引き換え係のパスワード | データベース（ハッシュ） | 引き換え端末のセッションが全部切れる |
| 係員暗証番号 | データベース（ハッシュ） | 暗証番号での交換ができなくなる |
| 初期パスワードの控え | `outputs/admin-access.txt` | — |

> [!重要]
> `outputs/admin-access.txt` はローカルの控えです。Gitにも公開ディレクトリにも置きません。共有が必要なときは、口頭か別経路で伝えてください。

禁止語ファイル `Config/forbidden` の鍵は、以前はソースコードに直接書いてありました。今は環境変数から読みますが、**過去の鍵はGitの履歴に残っています。** 禁止語の一覧を本当に秘密にしたい場合は、EncryptorToolで新しい鍵と初期化ベクトルを作ってファイルを暗号化し直し、環境変数も新しい値に替えてください。

## 認証と権限

- 参加者は署名付きのHttpOnly / SameSite=Strict Cookieで識別します。HTTPSではSecure属性が付きます。有効期限は30日。
- 管理画面のログインには2種類あります。

| ログイン | 使えるもの |
| --- | --- |
| 管理者パスワード | すべて（参加者一覧・設定・データ削除・景品引き換え） |
| 引き換え係のパスワード | 景品引き換え（10分以内の取り消しを含む）と運営マニュアルだけ |

- どちらのCookieも**8時間**で期限切れになり、`/api/admin` のパスに限定されます。ログインに使ったパスワードを変更すると、そのパスワードで開いたセッションは全部切れます。
- 管理APIは毎回サーバーで認証と権限を確認します。更新操作は同一オリジンからのみ受け付けます（CSRF対策）。
- 復旧コードは128ビットの乱数で、秘密鍵付きハッシュだけを保存します。管理画面・CSVにも含みません。
- 係員暗証番号・引き換え係のパスワード・サイトの合言葉もHMACでハッシュ化して保存し、APIの応答には含みません。

管理画面のwikiも同じ管理API経由で配信しています。未ログインでは `/api/admin/manual` が401を返し、マニュアル本文は取得できません。

## レート制限

| 対象 | 上限 |
| --- | --- |
| 管理画面へのログイン | 接続元ごとに15分20回 |
| サイトの合言葉 | 接続元ごとに15分60回 |
| 新規参加登録 | 接続元ごとに15分200件 |
| 復旧コードでの再ログイン | コードごとに15分10回／接続元ごとに15分100回 |
| 混み具合の報告 | 同じ参加者・同じ場所で5分1回／接続元ごとに15分300件 |
| 報酬の暗証番号 | コンプリート済みの参加者だけ。間違いは参加者1人あたり15分8回／接続元ごとに15分30回 |

接続元はHMACでハッシュ化して保存し、平文のIPはアプリのデータベースに残しません。正常なログインは接続元の回数に数えません（会場の回線を共有する参加者が互いに制限を食い合わないため）。

接続元のIPは、**Vercel上で動いているときだけ**転送ヘッダーから読みます。Vercelは受け取った転送ヘッダーを自分の見た値で置き換えるので偽装できません。それ以外の環境（LAN内のdev serverなど）では誰でも書き換えられるため、全端末で1つの枠を共有します。

## セキュリティヘッダー

すべての画面とAPIの応答に `next.config.ts` で次を付けています。

- `Content-Security-Policy`：スクリプト・通信・フォーム送信先をこのサイトに限定し、他サイトの枠内での表示（クリックジャッキング）を禁止します。
- `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`
- `Referrer-Policy: same-origin`：QRのリンクに含まれる署名を他サイトへ渡しません。
- `Permissions-Policy`：カメラはこのサイトだけ、マイク・位置情報などは使いません。
- `Strict-Transport-Security`（本番のみ）

## 運用で崩れやすい点

- **パスワードの口頭共有。** 班のグループチャットに貼ると、その時点で秘密ではなくなります。窓口の係員には管理者パスワードではなく引き換え係のパスワードを渡します。
- **暗証番号の使い回し。** 参加者の端末で入力するため、他で使っている番号は避けます。
- **管理画面を開いたまま離席。** セッションは8時間有効です。離席時はログアウトしてください。
- **スクリーンショット。** 参加者一覧を撮ると他人の学年・組・出席番号が写ります。
- **開催中の秘密値の変更。** QRとCookieが無効になります。

## 監査ログ

管理画面の「設定・データ管理」に最新30件の管理操作が出ます。記録されるのは操作の種別・対象・**操作した端末**（ログイン時の端末名。例：`admin:本部PC`、`desk:受付1`）で、学年・組・出席番号やCSVの中身は記録しません。パスワードを共有していても、どの端末の操作かは分かります。**理由は記録されません**ので、判断を伴う操作は受付のノートに残してください。

## 開催前後にやること

- [ ] 開催前：`npm audit` を確認する（残る指摘が開発用依存だけかを確かめる）
- [ ] 開催前：本番の環境変数が揃っていることを確認する（設定画面の上部に赤い警告が出ていない）
- [ ] 開催前：`/admin` に誤ったパスワードで入れないことを確認する
- [ ] 開催前：引き換え係のパスワードでログインし、参加者一覧が開けないことを確認する
- [ ] 開催後：係員暗証番号と引き換え係のパスワードを削除する
- [ ] 開催後：`ADMIN_PASSWORD` を変更する（当日知った人が多いほど早く）
- [ ] 開催後：CSVと控えのファイルを消す

事故が起きた場合の手順は [事故・障害時の対応](./incident.md) にあります。
