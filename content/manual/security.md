## 秘密情報の一覧

| 値 | 置き場所 | 変更の影響 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 環境変数 | 管理者セッションが全部切れる |
| `RALLY_SECRET` | 環境変数 | **既存QRと参加者Cookieが全部無効になる** |
| `TURSO_AUTH_TOKEN` | 環境変数 | 接続できなくなる |
| 係員暗証番号 | データベース（ハッシュ） | 交換できなくなる |
| 初期パスワードの控え | `outputs/admin-access.txt` | — |

> [!重要]
> `outputs/admin-access.txt` はローカルの控えです。Gitにも公開ディレクトリにも置きません。共有が必要なときは、口頭か別経路で伝えてください。

## 認証の仕組み

- 参加者は署名付きのHttpOnly / SameSite=Strict Cookieで識別します。HTTPSではSecure属性が付きます。有効期限は30日。
- 管理者Cookieは**8時間**で期限切れになり、`/api/admin` のパスに限定されます。
- 管理APIは毎回サーバーで認証を確認します。更新操作は同一オリジンからのみ受け付けます（CSRF対策）。
- 復旧コードは128ビットの乱数で、秘密鍵付きハッシュだけを保存します。管理画面・CSVにも含みません。
- 係員暗証番号もHMACでハッシュ化して保存し、参加者向けAPIの応答には含みません。

管理画面のwikiも同じ管理API経由で配信しています。未ログインでは `/api/admin/manual` が401を返し、マニュアル本文は取得できません。

## レート制限

| 対象 | 上限 |
| --- | --- |
| 管理者ログイン | 接続元ごとに15分10回 |
| 復旧コードでの再ログイン | コードごとに15分10回／接続元ごとに15分100回 |
| 報酬の暗証番号 | 参加者1人あたり15分8回 |

接続元はHMACでハッシュ化して保存し、平文のIPはアプリのデータベースに残しません。正常なログインは接続元の失敗回数に数えません（会場の回線を共有する参加者が互いに制限を食い合わないため）。

## 運用で崩れやすい点

- **パスワードの口頭共有。** 班のグループチャットに貼ると、その時点で秘密ではなくなります。
- **暗証番号の使い回し。** 参加者の端末で入力するため、他で使っている番号は避けます。
- **管理画面を開いたまま離席。** セッションは8時間有効です。離席時はログアウトしてください。
- **スクリーンショット。** 参加者一覧を撮ると他人の学年・組・出席番号が写ります。
- **開催中の秘密値の変更。** QRとCookieが無効になります。

## 監査ログ

管理画面の「設定・データ管理」に最新30件の管理操作が出ます。記録されるのは操作の種別と対象で、学年・組・出席番号やCSVの中身は記録しません。**理由は記録されません**ので、判断を伴う操作は受付のノートに残してください。

## 開催前後にやること

- [ ] 開催前：`npm audit` を確認する（残る指摘が開発用依存だけかを確かめる）
- [ ] 開催前：本番の環境変数が揃っていることを確認する
- [ ] 開催前：`/admin` に誤ったパスワードで入れないことを確認する
- [ ] 開催後：係員暗証番号を削除する
- [ ] 開催後：`ADMIN_PASSWORD` を変更する（当日知った人が多いほど早く）
- [ ] 開催後：CSVと控えのファイルを消す

事故が起きた場合の手順は [事故・障害時の対応](./incident.md) にあります。
