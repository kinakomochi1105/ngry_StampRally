## 当日の終わりにやること

- [ ] 管理画面の「新規参加登録を受け付ける」を外す
- [ ] 係員暗証番号と引き換え係のパスワードを削除する
- [ ] CSVを出力して管理者の端末に保管する
- [ ] スポットのQR台紙を回収する（貼ったままにしない）
- [ ] その日の障害・手動対応・判断をメモに残す

## 1週間以内

- [ ] 参加者数・押印数・交換数を集計し、学校へ報告する
- [ ] 振り返りを行う（下の観点）
- [ ] このwikiの該当ページを直す（**記憶が残っているうちに**）
- [ ] `ADMIN_PASSWORD` を変更する
- [ ] 次年度も同じデータベースを使う場合に備え、環境変数 `RALLY_EVENT_ID` を新しい値（例：`festival-2027`）にする段取りを残す。コードの変更は不要で、今年のデータは今年の識別子のまま残ります。QRは新しい識別子で印刷し直しになります
- [ ] データの削除日を関係者に周知する

## 削除日にやること

- [ ] CSVの保管を確認する（必要な集計が済んでいるか）
- [ ] 管理画面から「全参加データを削除」を実行する
- [ ] 紙の台紙を廃棄する（シュレッダー）
- [ ] 不要になったCSV・控えのファイルを消す

残るもの：設置場所、開催設定、発行済み一般客の連番、管理操作の履歴。次年度もこの設置場所を使うなら、そのまま残して構いません。

## 振り返りの観点

| 観点 | 見ること |
| --- | --- |
| 参加率 | 来場者数に対する参加者数。掲示の位置は足りたか |
| 完走率 | 参加者に対するコンプリート数。地点数は適切だったか |
| 交換率 | コンプリートに対する交換数。交換窓口の案内は届いたか |
| 混雑 | 特定スポットに偏らなかったか |
| 問い合わせ | 何がいちばん多かったか。掲示で減らせるか |
| 障害 | 原因と、来年の予防策 |

数字は管理画面の統計とCSVから出ます。**問い合わせの内容は記録していないと残りません。** 受付のノートが次年度の最大の資産です。

## 次の担当者に渡すもの

1. このwikiの場所（`/admin/wiki`。管理センター右上の「運営マニュアル」からも開けます）と、編集方法（[このwikiの編集方法](./authoring.md)）。
2. リポジトリと、本番環境（Vercel・Turso）へのアクセス。
3. 振り返りの記録と、受付ノートの要点。
4. 役割と判断基準（[運営体制と役割分担](./roles.md)）。**氏名は消して役割だけ残します。**

渡さないもの：管理者パスワードと係員暗証番号の現在値。**新しい担当者が自分で設定し直します。**

> [!重要]
> 引き継ぎで最も失われやすいのは「なぜそうしたか」です。地点数、掲示位置、交換の締め切り時刻——理由をマニュアルに書き足してください。理由がないルールは、翌年に理由なく破られます。
