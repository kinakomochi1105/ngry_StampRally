## 前日までに終えること

自動テストは論理の検査です。**カメラ・会場回線・実機のブラウザは手で確認するしかありません。**

```powershell
node --env-file=.env tests/api.mjs
node tests/i18n.mjs
node tests/manual.mjs
npx tsc --noEmit
npm run build
```

## 実機での通し稽古

本番と同じURL（本番ドメイン）を使い、スタッフの私物端末で1周します。

- [ ] iPhone + Safari で参加登録 → 復旧コード表示 → QR読み取り → コンプリート
- [ ] Android + Chrome で同じ流れ
- [ ] 一般客としての登録（学年・組を入力しない経路）
- [ ] 復旧コードでの再ログイン（Cookieを消してから）
- [ ] ニックネームの禁止語が実際にはじかれる
- [ ] 報酬の受け取り（窓口のスキャナ・カメラでバーコードを読み、参加者の画面が受け取り記録に切り替わるまで）
- [ ] 暗証番号での確定（予備の手順）
- [ ] 英語表示への切り替え、ダークテーマでの表示
- [ ] 印刷したQR台紙を掲示位置に貼った状態での読み取り

> [!重要]
> カメラはHTTPSまたはlocalhostでしか使えません。`http://192.168.x.x` で開くと「カメラを使用できません」になります。本番は必ずHTTPSで配信してください（[配信とインフラ](./infrastructure.md)）。

## 会場の回線

- 参加者が使う回線（校内Wi-Fi・携帯回線）で、実際の設置場所に立って表示速度を確かめます。**地下や鉄筋の奥は電波が届きません。**
- 届かない場所が見つかったら、スポットをそこから動かすのが最も早い対処です。
- 会場Wi-Fiを使う場合、同時接続数の上限を管理者に確認します。1000人の来場と1000人の同時接続は別の話です。

## 負荷について

ローカルでの試験は本番の性能保証になりません。1000人×6地点なら押印は最大6000件が目安です。開催前に本番相当の構成で負荷を確認し、公開基盤側のレート制限も設定してください（[規模と性能の見積もり](./capacity.md)）。

## リハーサルで作ったデータの片付け

- 検証用に登録した参加者は、管理画面の「参加者・進行状況」→「管理」から削除します。
- 一般客IDの連番は巻き戻りません。本番の1番が #5 などから始まっても問題はありませんが、気になる場合は開催前に全参加データを削除してから始めます。
- 変更した設定（学年・組・新規受付）を本番の値に戻したか確認します。

> [!注意]
> 全参加データの削除は元に戻せません。本番開始前の片付けに使うのは問題ありませんが、開催中は絶対に押さないでください。確認文字の入力が必要な作りになっているのは、このためです。
