# 文化祭スタンプラリー

スマートフォンで「生徒／一般客」を選んで参加し、サイト内カメラで設置QRを読み取るWebアプリです。初期設定は1〜3年、A〜E組、出席番号1〜50番。学年・組の名前と出席番号上限は管理者が変更できます。

## 参加者の流れ

1. 初回アクセスで生徒または一般客を選択。
2. 生徒は学年・組・出席番号とニックネームを入力。一般客もニックネームを入力し、#1 からの連番IDを自動発行。登録後に表示される復旧コードを控える。
3. スタンプ帳と設置場所一覧を確認し、画面下のボタンでQRを読み取る。
4. 公開中の全設置場所を集めるとコンプリート。

カメラ映像・QR画像は端末内で処理します。撮影済み画像の読み取りにも対応します。歩きながら使わないよう画面内で案内します。

設置場所タブでは、場所・階・案内をカードで確認できます。下部の「マップ」から階を選ぶと、登録された場所を簡易フロアマップで確認できます。マップは管理者が登録した場所の階情報から自動生成されるため、校舎の実際の平面図を掲載する場合は案内文や画像を別途用意してください。

## 管理者

`/admin` で管理者パスワードを入力します。初回パスワードはローカルの `outputs/admin-access.txt` に保存し、Sitesにはシークレットとして設定しています。公開ディレクトリやGitには保存しません。

- 参加区分別の人数、進行状況、完了人数。
- 全体ランキング（獲得数の降順、同数は最終押印時刻の昇順、同数同時刻は同順位）。0個は順位なし。
- 生徒／一般客の絞り込み、学年・組・番号・一般客IDの検索、50人ごとのページ表示。
- 個人の押印履歴表示、生徒の登録情報修正、押印リセット、参加者削除。
- CSV出力（最大10000人）。数式注入対策を行いUTF-8 BOM付きで出力。日時はCSVではUTC。
- 設置場所の追加・編集・表示順・公開／非公開、QR生成と印刷。
- 学年・組を任意の文字で追加・編集、出席番号上限、文化祭名、新規受付の停止。
- 全参加データ削除と操作履歴。削除には確認文字が必要。

新規データベースの設置場所は空です。管理者の「設置場所・QR」から実際の場所を追加するか「仮の6か所を作成」を押して編集してください。地点数は画面へ自動反映されます。非公開の場所は押印対象・達成条件から外れますが、過去の押印履歴は管理者が確認できます。開催中の対象変更は進行状況・順位に影響します。

同じ生徒の重複登録をDBの一意制約で防止します。学年・組・番号だけで既存の履歴にログインすることはできません。登録情報の自己申告は本人確認ではないため、他人の番号の先取りなどは受付で確認してください。Cookie削除・端末変更時にはニックネームと復旧コードで再ログインできます。履歴・参加ID・登録内容を引き継ぎ、旧端末のセッションを無効化します。復旧コードがない場合は元の端末で再発行するか受付へ相談してください。管理者による参加者削除では履歴も消えるため、復旧手段として安易に削除しないでください。

一般客IDはDBの連番をトランザクションで割り当て、同時登録でも重複させません。削除されたIDは再利用しません。別端末・Cookie削除による別IDの取得や、有効QRの写真共有は防げません。厳密な景品の一人一回引換には本人確認と別の引換管理が必要です。

## 再ログインとニックネーム

参加者画面の管理者・設定ボタンは表示しません。管理者は `/admin` を直接開いて認証してください。ボタンを隠すこと自体をアクセス制御には使っていません。

新規登録にニックネーム（2〜20文字、文字・数字・ハイフン・アンダースコア）を追加しました。本名は使わない案内を表示します。名前だけは秘密情報にならないため、再ログインにはサーバーが生成する128ビットのランダムな復旧コードも必要です。コードは発行時だけ表示し、DBには秘密鍵付きハッシュだけを保存します。管理者の一覧・CSVにもコードやハッシュを含めません。ニックネームは管理者の一覧・CSVに含みます。

ニックネームの重複は許容しますが、復旧コードで対象を一意に識別します。再ログインは名前とコードの両方を照合し、失敗の理由から参加者の有無が分からない応答にします。コードの英字大小、全角半角、空白とハイフンの入力差を吸収します。失敗はコードごと15分10回、接続元ごと15分100回まで。正常ログインは接続元の失敗回数に含めません。同じ会場回線を使う参加者の正常な再ログインで制限を消費しないためです。

コードを再発行すると古いコードは無効です。再ログイン・ログアウト時は旧Cookieをサーバー側でも無効化し、押印記録と参加者の対応をトランザクションで移行します。再ログインは新規受付停止中も可能ですが、押印の表示期間30日は延長しません。復旧コードを他人に渡すとアクセスされ得るため、本人だけで保管してください。

既存登録者にはニックネーム・コードを自動設定しません。現在ログイン中の端末の「ニックネームと復旧コードを設定」から登録できます。コード未設定のまま端末とCookieを失った場合は、ニックネームだけでアクセスを許可せず受付で対応します。

不適切名はサーバーで再検査し、NFKC正規化・英字大小・カタカナ/ひらがな・区切り記号の差をそろえて禁止語を判定します。制御文字・不可視文字・HTML等の記号は受け付けません。管理者を装う名前も禁止します。標準のNG語はサーバーのルートにある `Config/forbidden` に、EncryptorToolで作成したAES-CBC/PKCS7・Base64形式で保存します。Node.js実行時はファイルを読み直し、Workers配信時はビルドに埋め込んだファイルを使います。管理設定から追加禁止語を100件まで登録できます。判定はルールベースであり、あらゆる隠語・差別表現や文脈を完全に検出するものではなく、誤判定の可能性もあります。追加した禁止語は新規登録時に適用し、既存名の再ログインを後から妨げません。

## 開発

Node.js 24推奨（アプリ自体の最低要件は22.13）。

```powershell
npm ci
node scripts/setup-secret.mjs
node scripts/setup-admin.mjs
$env:WRANGLER_LOG_PATH='.wrangler/logs'
npx wrangler d1 migrations apply site-creator-d1 --local --config wrangler.local.json
npm run dev
```

管理者パスワードとQR署名秘密値は `.env` の `ADMIN_PASSWORD` と `RALLY_SECRET` に置きます。本番側にも同じ値をSitesのシークレットとして設定します。管理者パスワードは16文字以上（生成されるものは十分な乱数）。QR署名秘密値は32バイト以上の乱数。開催中に署名秘密値を変更すると既存QRとCookieが無効になります。管理者パスワードを変更すると管理者セッションも無効になります。

```powershell
node --env-file=.env tests/api.mjs
npx tsc --noEmit
npx oxlint app components/enrollment.tsx components/scanner.tsx lib db
npm run build
```

スキーマ変更時のみ `npm run db:generate` を実行し、SQLを点検してください。適用済みのSQLとスナップショットは変更しません。Sitesは保存したマイグレーションを配信時に適用します。

`tests/api.mjs` はローカルAPIへ接続し、ニックネーム判定・復旧・旧端末の失効・コード再発行・試行制限・登録・重複拒否・12人同時の一般客ID・ID再利用防止・24件同時押印・匿名の混み具合集計・本人の履歴分離・順位・管理権限・CSRF拒否・独自学年/組の設定・登録編集/削除・CSV・QRを検証します。テスト自身が作成した参加者は終了時に削除します。一般客の発行済み連番は巻き戻しません。初期地点がなければサンプル地点を作成します。既存設定は終了時に復元します。本番に対して実行できないようローカル接続だけを許可しています。

管理画面からのQR発行を通常の運用手順にしてください。`scripts/generate-qr.mjs` は `lib/event.ts` の初期サンプル地点専用で、DBで編集した地点の出力には使用しません。

## HTTPS化（Cloudflare Tunnel）

カメラでのQR読み取りは、ブラウザが安全なコンテキスト（HTTPSまたはlocalhost）でしか許可しません。LANのIPアドレスで開くと `カメラを使用できません` になるため、本番運用ではトンネル経由のHTTPSでアクセスします。ポート開放とルーター設定は不要です。

```powershell
winget install --id Cloudflare.cloudflared
cloudflared tunnel login
cloudflared tunnel create festival-rally
cloudflared tunnel route dns festival-rally hiroguru.mydns.jp
Copy-Item cloudflared.example.yml cloudflared.yml
```

`cloudflared.yml` の `tunnel` にトンネルID、`credentials-file` に `cloudflared tunnel create` が出力したJSONのパスを書きます。この認証情報ファイルはトンネルへのアクセス権を持つ秘密情報なので、`cloudflared.yml` ともどもGit管理から除外しています。

開催中は2つのプロセスを並行して動かします。

```powershell
npm run dev      # 別ウィンドウで
npm run tunnel
```

ドメインもCloudflareアカウントも用意せず試すだけなら `npm run tunnel:quick` が使えます。ログイン不要で、使い捨ての `https://xxxx-yyyy.trycloudflare.com` が即座に発行されます。`.trycloudflare.com` は既定の許可ホストに入れてあるため、毎回変わるURLでもdev serverを再起動する必要はありません。

別のホスト名を使う場合だけ、許可リストを上書きします。

```powershell
$env:RALLY_ALLOWED_HOSTS='example.com,.trycloudflare.com'; npm run dev
```

Cloudflareはエッジでhttpsを終端し、cloudflaredはローカルへhttpで転送します。このときサーバー側から見たURLはhttpのままなので、素の実装ではCookieの `Secure` 属性が付かず、CSRF対策のオリジン照合も食い違ってすべてのPOSTが403になります。`lib/server.ts` の `isSecureRequest` / `requestOrigin` が `X-Forwarded-Proto`・`X-Forwarded-Host`・`CF-Visitor` を優先して見ることで、この2点を解決しています。cloudflaredは外向きに接続するだけでオリジンは外部から直接叩けないため、転送ヘッダを信頼して問題ありません。

## データの保護と1000人規模の運用

参加者は署名付きHttpOnly/SameSite=Strict Cookieで識別し、HTTPSではSecure属性を付けます。有効期限は30日。ニックネーム、生徒の学年・組・出席番号と一般客IDはD1に保存します。氏名・メール・位置情報は収集しません。カメラ映像・画像はアップロードしません。CookieやQRの署名検証はサーバー側です。

管理者Cookieは8時間で期限切れになり、管理API専用パスに限定します。管理APIは毎回サーバーで認証を確認し、更新は同一オリジンのみ受け付けます。ログイン試行は接続元ごとに15分で10回まで。接続元はHMACでハッシュ化して保存し、平文IPはアプリDBに残しません。配信基盤側ではIPなどのアクセスログが記録され得ます。

管理画面・ランキング・CSVは一般参加者から取得できません。参加者は自分の登録情報と履歴だけを取得します。応答には `Cache-Control: no-store` を付け、SQLはプレースホルダーで実行します。押印の複合主キーで重複を防止し、参加者照合用の一意インデックスを設けています。ランキングは公開中の地点と30日以内の押印から計算します。

1000人×6地点の場合は押印最大6000件が目安です。参加者ページは登録・表示・押印時に加え、ログイン中は60秒ごとに匿名の混み具合を更新します。管理画面は50件ごとに取得します。1000人の来場と1000人の同時接続は異なり、ローカル試験は本番の性能保証ではありません。開催前に本番相当の負荷試験、会場Wi-Fi/携帯回線の確認、iPhone SafariとAndroid Chromeでのカメラ実機検証を行ってください。アプリAPIへの大量アクセスは、公開基盤のレート制限なども設定してください。

記録の物理削除は自動ではありません。主催者が開催後の削除日を決め、管理画面から全参加データを削除します。削除後も設定・設置場所・発行済み一般客の連番・管理操作の履歴は残ります。監査ログには生徒の学年/組/番号やCSV本体を記録しません。CSVと管理者パスワードは管理者だけで保管し、不要後に削除してください。

現在の公開サイトは所有者のみの確認用です。生徒・一般客向けの開催にはログイン不要の公開設定とHTTPSが必要です。学校名・開催日・設置場所の確定、QR掲示、スマホがない参加者の紙の台紙も準備してください。

## ビルドと確認の制限

手元のWindows環境では配信用ビルドがネイティブ処理で異常終了するため、Sites側のリモートビルドを使用します。型検査・静的検査・API試験はローカルで実行します。実機カメラ・ブラウザUI試験・本番1000人同時負荷試験は未実施です。WebMCPの設置場所表示ツールは対応環境での実行検証が未実施です。

サーバー側React/vinextと配信ツールは監査を受け修正版に更新済みです。残る監査指摘は開発用Drizzleのesbuild、Miniflareのsharpおよび依存元です。開発サーバーはループバックに限定しています。配布物の欠けたRolldown 1.2.8を避け、Viteが対応する1.2.7に固定しています。公開前に依存関係の監査を再確認してください。

## 言語とテーマ

参加者・管理画面のUIは日本語と英語に対応しています。初回はブラウザの優先言語リストから対応言語を選び、対応がなければ日本語にします。画面の Language / 言語 から手動選択でき、選択は端末のlocalStorageに保存します。「自動 / Auto」に戻すとブラウザ設定へ再び追従します。言語変更で登録やスタンプは変更されません。

文化祭名・設置場所の名称と案内・独自の学年/組・ニックネームは主催者や参加者が入力した表記を保持します。CSVの見出しと削除確認用の入力文字列は運用上、日本語で統一します。外部翻訳サービスへデータを送信しません。

ライト／ダークテーマは初回は prefers-color-scheme で端末設定に合わせ、画面右上の太陽／月アイコンでいつでも切り替えられます。選んだテーマは端末のlocalStorageに保存します。印刷時には白背景に切り替え、QRは常に白地に黒で出力します。

開発サーバー起動後の `node tests/i18n.mjs` で言語判定・翻訳・未対応文字列の保持・画面のHTTP応答を検証します。

## 混雑表示とフロアマップ

有効なQRが読み取られるたびに、場所IDと時刻だけを短期間の集計用テーブルへ記録します。個人ハッシュやニックネームは混雑集計へコピーしません。設置場所・マップには直近10分の読み取り件数を表示し、0〜2件を「空いている」、3〜7件を「少し動きあり」、8件以上を「混雑」とする目安です。件数は10分を過ぎると表示対象から外れ、管理画面の全参加データ削除でも同時に削除されます。正確な待ち時間や現在地を示すものではありません。

参加者向け画面はスマートフォン幅では縦1列、901〜999pxではスタンプ・設置場所を左、ヘルプと再ログインを右に配置する2カラム表示、1000px以上では左タブと横長コンテンツのPC／タブレット向け2カラム表示に切り替わります。展開式の使い方・再ログイン・参加データはメイン画面の下段に配置し、スタンプ帳や設置場所を広く表示します。下部ナビは「スタンプ帳」（メイン）、「設置場所」（一覧とマップ）、「特典」の3画面を共通の操作で切り替えられます。背景は端末の設定に合わせた白／黒、操作の強調色は青です。

## 報酬の受け取り

全スタンプを集めると、特典タブに「報酬を受け取る」が出ます。押すと「係員にこの画面を見せてください」という画面になり、**係員が暗証番号を入力して初めて交換が確定**します。参加者だけでは確定できません。確定すると、コンプリート日時と交換日時が入った印付きの受け取り記録が表示され、以後は何度開いても同じ記録が出ます（再交換はできません）。

暗証番号は管理画面の「設定」タブで4〜8桁の数字を登録します。**未設定のままだと参加者は報酬を受け取れません**ので、開催前に必ず設定してください。値はHMACでハッシュ化して保存し、参加者向けAPIの応答には一切含めません。参加者の端末で入力するものなので、他で使っていない番号にしてください。総当たり対策として、参加者1人あたり15分で8回まで試行できます。

交換の状況は管理画面の参加者一覧に「報酬交換」列として出ます。統計カードに交換済み人数、CSVに交換有無・コンプリート日時・交換日時が入ります。参加者管理ダイアログからは、紙の台紙で参加した人などを手動で交換済みにしたり、誤操作を取り消したりできます。確定・取り消しは監査ログに残ります。

## 個別スタンプ編集と初回ガイド

管理画面の「参加者・進行状況」→「管理」→「スタンプ達成状況を編集」で、各地点のスタンプを付与・取り消せます。各操作で即時保存し、参加者のスタンプ帳と管理側の集計・ランキングに反映します（開いたままの参加者画面は再読み込みが必要です）。新規付与は現在時刻、獲得済みの再付与は元の有効な日時を保持します。非公開地点の記録も編集できますが、達成数には含みません。操作は参加者ID・場所IDとともに管理履歴へ記録します。

新規登録後、復旧コードの保存確認を終えると、3ステップの使い方デモを表示します。場所の一覧・QR読み取り・コンプリートを画面の模式図で説明します。デモではカメラや押印APIを使用しません。スキップ・戻る・再表示に対応し、日本語/英語と動きを減らす設定に追従します。再ログインや復旧コードの再発行時には自動表示しません。
