# 文化祭スタンプラリー

スマートフォンのサイト内カメラで設置QRを読み取り、スタンプを集めるWebアプリです。設置場所一覧と印刷、全地点達成表示、QR画像読み取りに対応します。現在は開催準備用の仮の6地点です。

## 開発

Node.js 22.13以上（TypeScriptを直接読み込む補助スクリプトにはNode.js 24推奨）。

```powershell
npm ci
node scripts/setup-secret.mjs
npm run db:generate
$env:WRANGLER_LOG_PATH='.wrangler/logs'
npx wrangler d1 execute site-creator-d1 --local --file drizzle/0000_even_beast.sql --config wrangler.local.json
npm run dev -- --host 127.0.0.1
```

マイグレーション生成はスキーマ変更時のみ必要です。適用済みファイルは変更せず、新しいマイグレーションを追加します。

```powershell
node --env-file=.env scripts/generate-qr.mjs
node --env-file=.env tests/api.mjs
npx tsc --noEmit
npm run build
```

`outputs/qr-posters.html` をブラウザで開いて印刷します。設置場所の一覧は参加者サイトの「設置場所一覧」から印刷できます。生成済みのQRは参加前の押印を防ぐため公開フォルダやGitへ入れません。通常のカメラアプリから直接URLを開くQRではなく、サイト内の読み取り専用です。サイトへアクセスする案内QRは本番URL確定後に別途作成してください。

## 本番前に決めること

- 文化祭名・開催日・実際の設置場所を `lib/event.ts` と画面表示へ反映する。イベントごとに `event.id` を変更する。
- 今回のSitesは所有者のみの確認用公開。生徒・一般客向けにはログイン不要の公開設定とHTTPS URLが必要。
- iPhone Safari / Android Chromeでカメラ許可、拒否、QR画像、再アクセス、電波断からの再試行を現地で検証する。
- 現地のWi-Fi/携帯回線と利用ピークを確認し、本番相当の環境で負荷試験する。1000人の来場と1000人の同時接続は異なる。ローカル試験だけで本番性能を保証しない。
- 端末を持たない参加者向けに紙の台紙とスタッフ対応を用意する。
- 開催期間外の受付停止や景品交換管理が必要なら追加する。現在は景品引換機能なし。

## 保存・セキュリティ

- Cloudflare D1が押印の正本。保存項目はイベントID、参加者のハッシュ、地点ID、押印日時だけ。氏名・メール・位置情報を収集しない。カメラ映像/画像を送信しない。
- 参加者は暗号学的乱数とHMAC署名を持つHttpOnly / SameSite=Strict Cookieで識別。HTTPSではSecureも付く。期限は発行から30日。Cookie削除・端末変更・シークレットモード終了時の復元はできない。
- 各QRはイベント・地点に対するHMAC署名を検証。秘密値は `.env` とSitesのシークレット `RALLY_SECRET` にのみ保存。32バイト以上の乱数を使用。更新すると発行済みQRとセッションが使えなくなるため開催中は変更しない。
- `(event_id, participant_hash, spot_id)` の複合主キーで重複をDBレベルで防止。再試行も安全。取得クエリは参加者別のキーを使い、全員の記録を配信しない。SQLはプレースホルダーで実行。
- 押印APIは同一オリジン・JSONのみ、本文2KB以下。QR署名確認後にDBへアクセスする。QR内容をURLとして開かない。
- 1人6地点×1000人なら最大6000件が目安。新規参加だけではDBに書き込まず、取得/押印時だけ通信し、定期ポーリングしない。攻撃や自動化による大量アクセスは配信基盤のレート制限等を本番側で別途設定する。
- 写真で共有された有効QRからの押印や、Cookieを消しての再参加は防げない。景品の厳密な一人一回管理には別の参加証明と引換済み管理が必要。
- 履歴の表示対象は30日以内。物理削除は自動実行しない。主催者が終了後の削除日（例:開催終了30日後）を定め、管理されたD1操作で `DELETE FROM stamps WHERE event_id = 'festival-2026';` を実行する。対象とバックアップ方針を確認してから実行する。
- 運営者だけがDBと秘密値へアクセスできるよう管理する。配信基盤のログにはIPなどが含まれ得るため、基盤側のアクセス権・保持期間も確認する。個人別のCSV書き出しを公開しない。

## 検証の範囲

`tests/api.mjs` は実際のローカルAPIへ接続し、他参加者との分離・復元・同時重複押印・改ざんQR・別オリジン・偽造Cookie・過大入力・不正JSON・全達成を確認します。試験データはローカルDBだけに保存します。本番の1000人同時負荷試験や実機カメラ検証は含みません。

WebMCP対応ブラウザでは設置場所一覧を開く補助ツールを提供します。対応環境でのツール実行検証は未実施です。

依存関係の監査でサーバー側React / vinextと配信ツールを修正版へ更新済みです。残存する監査指摘は開発用Drizzleのesbuild、Miniflareのsharpとその依存元です。アプリは画像をサーバーで処理せず、開発サーバーはループバックに限定します。互換性を壊す強制ダウングレードは適用していません。本番前に監査を再実行し、上流の修正版を確認してください。

ビルド依存のRolldownは、1.2.8の任意配布物の欠落を避けるため、Viteの対応範囲内の1.2.7に固定しています。
