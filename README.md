# 文化祭スタンプラリー

スマートフォンで「生徒／一般客」を選んで参加し、設置QRを読み取るWebアプリです。設置QRはサイトへのリンクなので、スマホ標準のカメラやQRアプリで読み取ってもサイトが開き、スタンプが自動で押されます。サイト内のカメラからも従来どおり読み取れます。初期設定は1〜3年、A〜E組、出席番号1〜50番。学年・組の名前と出席番号上限は管理者が変更できます。

## 参加者の流れ

0. 合言葉が設定されている場合は、最初に合言葉を入力（設定していなければ表示されません）。
1. 初回アクセスで生徒または一般客を選択。
2. 生徒は学年・組・出席番号とニックネームを入力。一般客もニックネームを入力し、#1 からの連番IDを自動発行。登録後に表示される復旧コードを控える。
3. 設置場所のQRをスマホのカメラで読み取る（サイトが開き、自動で押印）。サイト内の「QRコードを読み取る」ボタンからも読み取れる。
4. 公開中の全設置場所を集めるとコンプリート。

カメラ映像・QR画像は端末内で処理します。撮影済み画像の読み取りにも対応します。歩きながら使わないよう画面内で案内します。

設置QRは `https://<公開アドレス>/s/<場所ID>/<署名>` という形のリンクです。読み取るとこのアドレスが開き、参加者画面へ転送されてから、その画面が押印APIへ署名付きの同じリンクを送ります。押印はブラウザからの同一オリジン送信だけで行うため、参加Cookie（SameSite=Strict）が付かない経路で開かれても押印できます。未登録の状態で読み取った場合は、読み取った場所を覚えたまま登録画面を表示し、登録が終わった時点で自動的に押印します。

設置場所タブでは、場所・階・案内をカードで確認できます。各カードから今の混み具合を報告でき、集まった報告の平均を全員の画面に表示します。「マップを見る」を押すと会場マップが開きます。管理者が校舎の見取り図を登録していればその画像を表示し、教室の枠をタップするとその団体の案内が開きます。未登録の間は、登録された場所の階情報から作る簡易フロアマップを表示します。

## 管理者

`/admin` で管理者パスワードを入力します。初回パスワードはローカルの `outputs/admin-access.txt` に保存し、本番へはVercelの環境変数として設定します。公開ディレクトリやGitには保存しません。

- 参加区分別の人数、進行状況、完了人数。
- 全体ランキング（獲得数の降順、同数は最終押印時刻の昇順、同数同時刻は同順位）。0個は順位なし。
- 生徒／一般客の絞り込み、学年・組・番号・一般客IDの検索、50人ごとのページ表示。
- 個人の押印履歴表示、生徒の登録情報修正、押印リセット、参加者削除。
- CSV出力（最大10000人）。数式注入対策を行いUTF-8 BOM付きで出力。日時はCSVではUTC。
- 設置場所の追加・編集・表示順・公開／非公開、QR生成と印刷。
- 会場マップの登録（見取り図の画像を貼り付け、枠を描いて団体へリンク）。
- 学年・組を任意の文字で追加・編集、出席番号上限、文化祭名、新規受付の停止。
- 全参加データ削除と操作履歴。削除には確認文字が必要。
- 景品引き換え係のパスワード（景品引き換えだけを使える別のログイン）。

ログイン画面では端末名（例：本部PC、受付1）も入力できます。端末名は署名付きCookieに入り、操作履歴に `admin:本部PC` のように記録されます。パスワードを共有していても、どの端末の操作かが分かります。

管理者が「設定・データ管理」で**景品引き換え係のパスワード**を設定すると、そのパスワードでログインした端末は景品引き換え（直前10分以内の取り消しを含む）と運営マニュアルだけを使えます。参加者一覧・設定・データ削除のAPIは403を返します。窓口のボランティアに管理者パスワードを渡す必要はありません。引き換え係のパスワードを変更すると、ログイン中の引き換え端末はすべてログアウトされます。

新規データベースの設置場所は空です。管理者の「設置場所・QR」から実際の場所を追加するか「仮の6か所を作成」を押して編集してください。地点数は画面へ自動反映されます。非公開の場所は押印対象・達成条件から外れますが、過去の押印履歴は管理者が確認できます。開催中の対象変更は進行状況・順位に影響します。

同じ生徒の重複登録をDBの一意制約で防止します。学年・組・番号だけで既存の履歴にログインすることはできません。登録情報の自己申告は本人確認ではないため、他人の番号の先取りなどは受付で確認してください。Cookie削除・端末変更時にはニックネームと復旧コードで再ログインできます。履歴・参加ID・登録内容を引き継ぎ、旧端末のセッションを無効化します。復旧コードがない場合は元の端末で再発行するか受付へ相談してください。管理者による参加者削除では履歴も消えるため、復旧手段として安易に削除しないでください。

一般客IDはDBの連番をトランザクションで割り当て、同時登録でも重複させません。削除されたIDは再利用しません。別端末・Cookie削除による別IDの取得や、有効QRの写真共有は防げません。厳密な景品の一人一回引換には本人確認と別の引換管理が必要です。

## 管理者向けマニュアルwiki

運営用マニュアルを `/admin/wiki` に内蔵しています（管理画面とは別の画面です。管理センター右上の「運営マニュアル」から開きます）。本文は `content/manual/*.md` のMarkdownで、体制・準備・当日運営・受付・報酬・トラブル対応・個人情報・セキュリティ・インシデント・インフラ・性能・アクセシビリティ・紙の代替手段・引き継ぎ・編集方法の21ページを、7分類に分けて収録します。

- `/admin/wiki` は入口です。「当日よく開くページ」と、分類ごとのカード一覧（対象者・要約・タグ付き）を表示します。
- `/admin/wiki/<slug>` が本文です。URLがページごとに分かれるので、共有・ブックマーク・再読み込み・ブラウザの戻るがそのまま使えます。
- 検索は入力しながら実行し、本文まで含めて探します。`/` キーで検索欄へ移動、Escで解除します。
- 本文の左に全ページの一覧、右にページ内の目次を固定表示します（画面が狭いときは折りたたみに切り替わります）。
- 前後のページへの移動、原稿のMarkdown表示とコピー、本文だけを出す印刷に対応します。

ページはリポジトリのファイルです。アプリからの編集機能は設けていません。配信先のファイルシステムが読み取り専用であることと、変更履歴を残して誤りを戻せるようにすることが理由です。各ページ先頭の `---` ブロックに `title`・`category`・`audience`・`summary`・`updated`・`order`（と任意の `tags`）を書きます。不足や書式違いは読み込み時にファイル名付きのエラーになります。`order` は10刻みで、分類の並び順もこの値で決まります。`[受付](./reception.md)` と書くとページ間リンクになります。

配信は管理APIと同じ `/api/admin/manual` 経由です。管理者Cookieは `/api/admin` に限定されているため、未ログインでは401でマニュアル本文を取得できません。Markdownの変換は外部ライブラリを使わず `lib/markdown.ts` が行い、原稿を先にすべてエスケープしてから対応記法（見出し・箇条書き・チェックリスト・表・コード・引用・`> [!重要]` の囲み・リンク）だけをタグへ変換します。本文に書いたHTMLは文字として表示され、`javascript:` などのURLはリンクになりません。Markdownはどのモジュールからも import しないため、`next.config.ts` の `outputFileTracingIncludes` で `content/manual` を配信物へ含めています。開発中はリクエストごとに読み直し、本番では1インスタンスにつき1回読み込みます。

画面のスタイルは、このルートだけが読み込む `app/admin/wiki/wiki.css` に置いています。`globals.css` へ追記する形にしたところ、本番で配信されたCSSチャンクに追記分が入らない（ビルドキャッシュ由来と見られる）事象があったため、独立したファイルにしています。表示が古いままのときは、ビルドキャッシュを使わずに再デプロイしてください。

UIの文言は日本語と英語に対応しますが、マニュアル本文は日本語のまま表示します（主催者が書いた文章を機械的に訳さない方針です）。`npm run test:manual` がメタ情報・`order` の重複・ページ間リンクの行き先・変換結果のエスケープと検索用テキストの整形を検査します。dev serverは不要です。`npm run test:i18n` は `/admin/wiki` と個別ページのHTTP応答も確認します。

## サイトの合言葉（閲覧パスワード）

管理画面の「設定・データ管理」で合言葉を登録すると、参加者サイトは合言葉を入力するまで何も表示しなくなります。校内限定の催しを外部に開かないための入口の鍵で、**未設定なら誰でも利用できる**従来どおりの動作です。

入力するとサーバーが署名付きのCookie（`rally_gate`、HttpOnly・SameSite=Strict・30日）を発行し、以降の参加者APIはこれを確認します。署名には保存中の合言葉のハッシュを含めるため、**合言葉を変更・削除すると発行済みのCookieはすべて無効**になり、各端末は次のアクセスで入力し直します。合言葉はHMACでハッシュ化して保存し、平文はサーバーにもAPI応答にも残りません。

閉じるのは参加者向けAPI（スタンプ帳・登録・押印・混雑報告・再ログイン・報酬）だけです。**管理センター `/admin` と `/api/admin/*` は合言葉の外側**に置いています。入力ミスや伝達ミスで合言葉が分からなくなったとき、それを解除できる唯一の画面まで閉じてしまわないためです。総当たり対策として、接続元ごとに15分60回まで試行できます（会場の回線を全員で共有する前提のため、管理者ログインより緩めです）。

合言葉は掲示・配布物で来場者に伝えてください。ページのHTMLとスクリプト自体は合言葉なしでも取得できます（データを持たない静的な画面のため）。守っているのは文化祭のデータであって、アプリの存在自体ではありません。

## 再ログインとニックネーム

参加者画面の管理者・設定ボタンは表示しません。管理者は `/admin` を直接開いて認証してください。ボタンを隠すこと自体をアクセス制御には使っていません。

新規登録にニックネーム（2〜20文字、文字・数字・ハイフン・アンダースコア）を追加しました。本名は使わない案内を表示します。名前だけは秘密情報にならないため、再ログインにはサーバーが生成する128ビットのランダムな復旧コードも必要です。コードは発行時だけ表示し、DBには秘密鍵付きハッシュだけを保存します。管理者の一覧・CSVにもコードやハッシュを含めません。ニックネームは管理者の一覧・CSVに含みます。

ニックネームの重複は許容しますが、復旧コードで対象を一意に識別します。再ログインは名前とコードの両方を照合し、失敗の理由から参加者の有無が分からない応答にします。コードの英字大小、全角半角、空白とハイフンの入力差を吸収します。失敗はコードごと15分10回、接続元ごと15分100回まで。正常ログインは接続元の失敗回数に含めません。同じ会場回線を使う参加者の正常な再ログインで制限を消費しないためです。

コードを再発行すると古いコードは無効です。再ログイン・ログアウト時は旧Cookieをサーバー側でも無効化し、押印記録と参加者の対応をトランザクションで移行します。再ログインは新規受付停止中も可能ですが、押印の表示期間30日は延長しません。復旧コードを他人に渡すとアクセスされ得るため、本人だけで保管してください。

既存登録者にはニックネーム・コードを自動設定しません。現在ログイン中の端末の「ニックネームと復旧コードを設定」から登録できます。コード未設定のまま端末とCookieを失った場合は、ニックネームだけでアクセスを許可せず受付で対応します。

不適切名はサーバーで再検査し、NFKC正規化・英字大小・カタカナ/ひらがな・区切り記号の差をそろえて禁止語を判定します。制御文字・不可視文字・HTML等の記号は受け付けません。管理者を装う名前も禁止します。標準のNG語はサーバーのルートにある `Config/forbidden` に、EncryptorToolで作成したAES-256-CBC/PKCS7・Base64形式で保存します。復号の鍵と初期化ベクトルは環境変数 `NICKNAME_BLOCKLIST_KEY`（32バイト）と `NICKNAME_BLOCKLIST_IV`（16バイト）で渡します（以前はソースに直書きしていたため、過去の鍵はGitの履歴に残っています。一覧を秘密にしたい場合は新しい鍵で暗号化し直してください）。未設定・不一致のときは新規登録を拒否し、管理画面の設定タブに警告を出します。サーバーは1インスタンスにつき1回このファイルを読みます。どのモジュールからも import しないファイルなので、配信物に含めるために `next.config.ts` の `outputFileTracingIncludes` で指定しています。管理設定から追加禁止語を100件まで登録できます。判定は部分一致なので、禁止語を含むだけの普通の名前（`Yamashita` の shit、`badminton` の admin、`シネマ` のしね など）は標準の許可語で救済し、管理設定からも許可する語を100件まで追加できます。許可語を取り除いた位置には区切りを残すため、前後の文字をつなげて禁止語を作ることはできません。判定はルールベースであり、あらゆる隠語・差別表現や文脈を完全に検出するものではなく、誤判定の可能性もあります。追加した禁止語は新規登録時に適用し、既存名の再ログインを後から妨げません。

## 開発

Node.js 24推奨（アプリ自体の最低要件は22.13）。

```powershell
npm ci
node scripts/setup-secret.mjs
node scripts/setup-admin.mjs
npm run db:migrate
npm run dev
```

管理者パスワードとQR署名秘密値は `.env` の `ADMIN_PASSWORD` と `RALLY_SECRET` に置きます。変数の一覧と意味は `.env.example` にあります。

| 変数 | 内容 |
| --- | --- |
| `RALLY_SECRET` | QR・Cookieの署名秘密値（32バイト以上の乱数）。開催中に変更すると既存QRとCookieが無効 |
| `ADMIN_PASSWORD` | 管理者パスワード（16文字以上）。変更すると管理者セッションも無効 |
| `RALLY_SITE_URL` | QRに入れる公開アドレス（例 `https://rally.example.jp`）。未設定なら管理画面を開いているアドレス |
| `RALLY_EVENT_ID` | 文化祭の識別子。未設定なら `festival-2026`。翌年は新しい値にするだけで、同じデータベースに前年のデータを残したまま始められる（QRは印刷し直し） |
| `NICKNAME_BLOCKLIST_KEY`・`NICKNAME_BLOCKLIST_IV` | `Config/forbidden` の鍵と初期化ベクトル（EncryptorToolの `config.toml` の値） |
| `TURSO_DATABASE_URL`・`TURSO_AUTH_TOKEN` | libSQLの接続先（ローカルは `file:local.db`） |
| `MIGRATE_PREVIEW_DATABASE` | プレビューデプロイ専用のデータベースにだけ `1`（後述） |

未設定のときは管理画面を開いているアドレスをそのままQRに使うため、localhostやLANのアドレスで発行したQRを印刷しないよう注意してください。

```powershell
npm run typecheck   # next typegen && tsc --noEmit
npm run lint        # oxlint
npm test            # 単体テストとマニュアルの検査（サーバー不要）
npm run test:api    # dev serverに対するAPI試験
npm run test:i18n   # 翻訳の網羅とページのHTTP応答
npm run build
```

テストはNodeから直接アプリのTypeScriptを読みます。`tests/support/register.mjs` が `@/` の別名と拡張子なしのimportを解決し、プロジェクト内の `.ts` をTypeScriptコンパイラで変換します。単体テスト（`tests/unit/`）はニックネーム判定と許可語、引き換えコード、QRの解釈、CSVの数式対策、設定の読み込みと検証、HMAC署名、管理セッション（役割・端末名・改ざん検知、インメモリのlibSQLで引き換え係のパスワード変更による失効まで）、HTTPの共通処理（エラー応答とログ、接続元の扱い、CSRF、本文の上限）、`RALLY_EVENT_ID` を検査します。

`tests/api.mjs` はローカルAPIへ接続し、ニックネーム判定と許可語・復旧・旧端末の失効・コード再発行・試行制限・登録・重複拒否・12人同時の一般客ID・ID再利用防止・24件同時押印・匿名の混み具合集計・本人の履歴分離・順位・管理権限と引き換え係の権限・操作履歴の端末名・CSRF拒否・独自学年/組の設定・登録編集/削除・CSV・アイコン配信・セキュリティヘッダー・QRを検証します。テスト自身が作成した参加者は終了時に削除します。本番に対して実行できないようローカル接続だけを許可しています。**テストはデータを書き込むため**、`.env.local` に本番Tursoの値がある場合は `.env.development.local` に `TURSO_DATABASE_URL=file:local.db` を置き、dev serverがローカルのデータベースを使うようにしてください。

スキーマ変更時のみ `npm run db:generate` を実行し、SQLを点検してください。適用済みのSQLとスナップショットは変更しません。

管理画面からのQR発行を通常の運用手順にしてください。`scripts/generate-qr.mjs` は `lib/event.ts` の初期サンプル地点専用で、DBで編集した地点の出力には使用しません。実行には `RALLY_SITE_URL` が必要です。

開催中に公開アドレスを変えると、印刷済みのQRのリンク先も変わってしまいます。アドレスを決めてからQRを印刷してください（署名は場所IDと `RALLY_SECRET` だけで決まるため、旧アドレスのQRを手入力で開いても押印自体は成立します）。

### CI

`.github/workflows/ci.yml` が push と Pull Request ごとに、型検査・静的検査・`npm test`・本番ビルドを実行し、本番サーバーを起動して `test:api` と `test:i18n` まで流します。秘密値・SQLiteのデータベース・暗号化した禁止語リストはその場で使い捨てで作るため（`tests/support/blocklist.mjs`）、リポジトリのSecretsに登録するものはありません。

## LAN内HTTPS（インターネットなしで連続スキャン）

会場にインターネットがない、またはドメインを用意できない場合の手段です。`http://192.168.x.x` は secure context ではないため、ブラウザが `getUserMedia` を拒否して連続スキャンができません。自己署名証明書でLANをHTTPS化すると、この制限を正規の方法で解除できます。

```powershell
npm run setup:https
npm run dev:https
```

`scripts/setup-https.mjs` が、この端末のLAN IPをすべてSANに含む証明書を `.certs/` に作ります（秘密鍵はGit管理外）。表示された `https://192.168.x.x:3000/` をスマホで開いてください。

**トレードオフ**: この証明書を保証する第三者がいないため、**参加者の端末ごとに1回、警告画面が出ます**（「この接続ではプライバシーが保護されません」→ 詳細設定 → アクセスする）。1000人規模でこれを案内するのは現実的ではなく、セキュリティ警告を無視する習慣もつけさせたくありません。**スタッフ端末での検証や小規模開催向け**と考えてください。インターネットが使える場合はVercelでの配信を優先してください。なおVercel以外では転送ヘッダーの接続元IPを信用しないため、試行回数の制限は全端末で1つの枠を共有します。

## Vercelへの配信

ホスティングはVercel、データベースはlibSQL（Turso）です。以前使っていた Cloudflare Tunnel での公開は廃止しました（転送ヘッダーの偽装で試行回数の制限をすり抜けられたため）。

1. Tursoでデータベースを作成し、URLと認証トークンを取得します。

```bash
turso db create ngry-stamprally
turso db show ngry-stamprally --url
turso db tokens create ngry-stamprally
```

2. 取得した値でマイグレーションを適用します（PowerShellの例）。

```powershell
$env:TURSO_DATABASE_URL='libsql://<db>.turso.io'; $env:TURSO_AUTH_TOKEN='<token>'; npm run db:migrate:remote
```

3. Vercelのプロジェクト設定（Production）で、`TURSO_DATABASE_URL`・`TURSO_AUTH_TOKEN`・`ADMIN_PASSWORD`・`RALLY_SECRET`・`NICKNAME_BLOCKLIST_KEY`・`NICKNAME_BLOCKLIST_IV` を環境変数に登録します（必要なら `RALLY_SITE_URL`・`RALLY_EVENT_ID` も）。**禁止語リストの2つが無いと新規登録がすべて失敗します。**

4. リポジトリをVercelに接続すると `npm run build` が実行されます。`next build` が成功したあとで未適用のマイグレーションを本番データベースへ適用するため、ビルドに失敗したときにスキーマだけが先に進むことはありません。**プレビューデプロイでは適用しません**（未レビューのブランチが本番のスキーマを変えないため）。プレビュー専用のデータベースを使う場合だけ、そのプレビューに `MIGRATE_PREVIEW_DATABASE=1` を設定します。

データベースへはDrizzle ORM（`drizzle-orm/libsql`）でアクセスし、列名と結果の型を `db/schema.ts` から得ます。複数の文を1つの書き込みトランザクションで流すときは `db/index.ts` の `writeBatch`（libSQLの `write` モード）を使います。順位計算など集計の重いクエリは `sql` テンプレートで書いています。

## データの保護と1000人規模の運用

参加者は署名付きHttpOnly/SameSite=Strict Cookieで識別し、HTTPSではSecure属性を付けます。有効期限は30日。ニックネーム、生徒の学年・組・出席番号と一般客IDはlibSQL（Turso）に保存します。氏名・メール・位置情報は収集しません。カメラ映像・画像はアップロードしません。CookieやQRの署名検証はサーバー側です。

管理者・引き換え係のCookieは8時間で期限切れになり、管理API専用パスに限定します。管理APIは毎回サーバーで認証と役割を確認し、更新は同一オリジンのみ受け付けます。試行回数は `lib/limits.ts` にまとめています：ログインは接続元ごとに15分20回、合言葉は60回、新規登録は200件、混み具合の報告は300件（同じ参加者・場所は5分1回）、復旧コードはコードごと10回・接続元ごと100回、報酬の暗証番号はコンプリート済みの参加者だけが参加者ごと8回・接続元ごと30回まで間違えられます。接続元のIPはVercel上でだけ転送ヘッダーから読み（Vercelが上書きするため偽装できない）、HMACでハッシュ化して保存し、平文IPはアプリDBに残しません。配信基盤側ではIPなどのアクセスログが記録され得ます。

すべての応答に `next.config.ts` でContent-Security-Policy（スクリプト・通信・フォーム送信先を自サイトに限定、`frame-ancestors 'none'`）、`X-Frame-Options: DENY`、`Referrer-Policy: same-origin`、`Permissions-Policy`（カメラは自サイトのみ）、本番では `Strict-Transport-Security` を付けます。Next.jsのハイドレーションと初回描画前のテーマ適用がインラインスクリプトのため、scriptには `'unsafe-inline'` を残しています（nonceにすると全ページが動的描画になるため）。QRの転送（`/s/...`）は相対パスへリダイレクトし、ヘッダーで別ホストへ飛ばされないようにしています。

APIの失敗は `lib/http.ts` の `route()` で統一しています。利用者が対処できる失敗（入力・認証・上限）は `UserError` の文言と状態コードで返し、それ以外は日本語の定型文と503で返したうえで、サーバーのログにSQLと原因だけを出します（ニックネームなどのバインド値は出しません）。

管理画面・ランキング・CSVは一般参加者から取得できません。参加者は自分の登録情報と履歴だけを取得します。応答には `Cache-Control: no-store` を付け、SQLはプレースホルダーで実行します。押印の複合主キーで重複を防止し、参加者照合用の一意インデックスを設けています。ランキングは公開中の地点と30日以内の押印から計算します。

1000人×6地点の場合は押印最大6000件が目安です。参加者ページは登録・表示・押印時に加え、ログイン中は60秒ごとに匿名の混み具合を更新します。管理画面は50件ごとに取得します。1000人の来場と1000人の同時接続は異なり、ローカル試験は本番の性能保証ではありません。開催前に本番相当の負荷試験、会場Wi-Fi/携帯回線の確認、iPhone SafariとAndroid Chromeでのカメラ実機検証を行ってください。アプリAPIへの大量アクセスは、公開基盤のレート制限なども設定してください。

記録の物理削除は自動ではありません。主催者が開催後の削除日を決め、管理画面から全参加データを削除します。削除後も設定・設置場所・発行済み一般客の連番・管理操作の履歴は残ります。監査ログには生徒の学年/組/番号やCSV本体を記録しません。CSVと管理者パスワードは管理者だけで保管し、不要後に削除してください。

現在の公開サイトは所有者のみの確認用です。生徒・一般客向けの開催にはログイン不要の公開設定とHTTPSが必要です。学校名・開催日・設置場所の確定、QR掲示、スマホがない参加者の紙の台紙も準備してください。

## ビルドと確認の制限

作業コピーがexFATのドライブにあるとシンボリックリンクを作成できず、本番ビルドもTurbopackのdev serverも動きません（`@libsql/client` を読み込むAPIが500になります）。NTFSのパスで作業するか、Vercelのリモートビルドを使ってください。NTFS上では型検査・静的検査・単体テスト・API試験・i18n試験・本番ビルドがすべて通過することを確認しています。QR読み取りは、写真を選ぶ経路でWeb Workerでの解析から押印までをブラウザで確認しました（検証に使ったブラウザには `BarcodeDetector` がないためWorker側の経路です）。

実機カメラ・実機ブラウザ（iPhone Safari・Android Chromeでの `BarcodeDetector` 経路を含む）での操作試験・本番1000人同時負荷試験は未実施です（wikiの印刷結果も目視確認は未実施）。WebMCPの設置場所表示ツールは対応環境での実行検証が未実施です。

公開前に `npm audit` で依存関係を再確認してください。

## 画面の構成とスタイル

画面は「参加者アプリ」と「管理センター」の2つで、どちらも同じトークンの上に載っています。

- `app/styles/tokens.css` に色・余白・角丸・影・文字サイズをまとめ、ライト／ダークと印刷はこのファイルだけで切り替わります。個々の画面は色の値を直接書きません。
- `app/globals.css` は読み込み順（tokens → base → ui → participant → dialogs → admin → motion → print）を宣言するだけで、それ自体にスタイルを持ちません。追記を重ねて同じ要素を何度も上書きしない構成にしています。
- 操作部品は最小44pxで、入力欄の文字は16px固定です（iOS Safariで入力時にページが拡大されないため）。ダイアログはスマホでは画面下からのシートに、640px以上では中央のカードになります。
- 参加者アプリは1024px未満では下部に1行のバー（スタンプ帳／設置場所／読み取る／マップ／特典）、1024px以上では本文の横にレールを出します。マークアップは共通で、CSSだけが切り替わります。
- 動きは `app/styles/motion.css` にまとめ、すべて `prefers-reduced-motion: no-preference` の中に置いています。動きを減らす設定の端末では最初から再生されません。
- テーマは `app/layout.tsx` の小さなスクリプトが初回描画前に適用するため、保存済みの選択が一瞬だけ反転して見えることはありません。
- 画面のロジックは `app/page.tsx` と `app/admin/page.tsx` が組み立てだけを行い、通信は `hooks/use-passport.ts`・`hooks/use-admin.ts`、表示は `components/participant/`・`components/admin/` に分かれています。ブラウザからのAPI呼び出しはすべて `lib/client.ts` を通り、JSONでない応答（クラッシュページなど）もそのまま画面に出さず、日本語の案内文に置き換えます。
- 混み具合の段階・しきい値・報告の選択肢は `lib/crowd.ts` にまとめ、APIと画面が同じ定義を読みます。
- サーバー側は `lib/http.ts`（共通のエラー処理・本文の読み取り・オリジン照合）、`lib/session.ts`（参加者Cookie）、`lib/admin.ts`（管理者／引き換え係のセッション）、`lib/limits.ts`（試行回数）、`lib/settings.ts`（設定と秘密値）、`lib/audit.ts`（操作履歴）、`lib/qr.ts`（QRの解釈と検証）に分かれ、各APIルートはそれを組み合わせるだけです。
- QRの読み取りは `lib/qr-decoder.ts` が担当します。端末に `BarcodeDetector` があればそれを使い、なければ `lib/qr-worker.ts` のWeb WorkerでjsQRを動かします。画面を開いている間の解析がメインスレッドを塞がず、電池の消費も抑えます。

## 言語とテーマ

参加者・管理画面のUIは日本語と英語に対応しています。初回はブラウザの優先言語リストから対応言語を選び、対応がなければ日本語にします。画面の Language / 言語 から手動選択でき、選択は端末のlocalStorageに保存します。「自動 / Auto」に戻すとブラウザ設定へ再び追従します。言語変更で登録やスタンプは変更されません。

文化祭名・設置場所の名称と案内・独自の学年/組・ニックネームは主催者や参加者が入力した表記を保持します。CSVの見出しと削除確認用の入力文字列は運用上、日本語で統一します。外部翻訳サービスへデータを送信しません。

ライト／ダークテーマは初回は prefers-color-scheme で端末設定に合わせ、画面右上の太陽／月アイコンでいつでも切り替えられます。選んだテーマは端末のlocalStorageに保存します。印刷時には白背景に切り替え、QRは常に白地に黒で出力します。

開発サーバー起動後の `npm run test:i18n` で言語判定・翻訳・未対応文字列の保持・画面のHTTP応答を検証します。

## 混雑表示とフロアマップ

混み具合には2つの情報源があります。

**自動計測**：有効なQRが読み取られるたびに、場所IDと時刻だけを短期間の集計用テーブルへ記録します。個人ハッシュやニックネームは混雑集計へコピーしません。直近10分の読み取り件数を、0〜2件「空いている」、3〜7件「少し動きあり」、8件以上「混雑」の目安として表示します。

**参加者の報告**：設置場所の各カードにある「混み具合を報告」から、「すぐ押せる」「少し待つ」「行列ができている」の3択で今の様子を送れます。QRの前に並んでいる列は読み取り件数には現れないため、実際の待ち時間に近いのはこちらです。報告は**直近20分の平均**として表示し、報告が1件でもある場所は自動計測より報告を優先します。バッジの下段に「みんなの報告 平均2.0 · 3件」のように根拠を書き、どちらを見ているのか分かるようにしています。

報告の行も場所ID・段階・時刻だけで、送信者を示す値は持ちません。連投は `login_attempts` に置く短命のキー（参加者の行IDと場所から作るハッシュ）で同じ場所につき5分に1回までに制限し、報告そのものの隣に識別子を残さない形にしています。行IDを使うので、再ログインで端末を変えても制限は戻りません。接続元ごとにも15分300件までに抑え、参加証を大量に作って混雑表示を操作することを防ぎます。報告は20分を過ぎると次の書き込み時に削除され、管理画面の全参加データ削除でも自動計測ぶんと一緒に消えます。いずれも正確な待ち時間や現在地を示すものではありません。

## 会場マップ

管理者が「会場マップ」で校舎の見取り図（PNG・JPEG）を登録できます。画像の上をドラッグして枠を描き、枠ごとに設置場所（団体）を選ぶと、参加者はその枠をタップして団体の案内・混み具合・獲得状況を開けます。スタンプのない場所は「リンクなし」を選び、表示名（受付・トイレなど）だけを持たせられます。

描いた枠はドラッグで移動、右下の角で大きさを変更できます。枠を選べば矢印キーでも動かせます（Shiftで大きさ、Altで大きく移動）。枠ごとに**枠の色と文字の色**を指定でき（`#RRGGBB` のみ保存し、それ以外の値は破棄します）、未指定の枠はテーマの配色に従います。

枠は画像の縦横に対する割合で保存するため、画面幅が変わっても、あとから画像を差し替えても同じ位置に残ります。画像は長辺2000pxまで縮小してデータベースに保存し、参加者へは `/api/map/<ID>?v=<更新時刻>` から画像として配信します。画面データには画像を含めないので、1分ごとの更新で毎回送り直すことはありません。設置場所にアップロードしたアイコン（最大96KB）も同じで、参加者のスタンプ帳には `/api/spot-icon/<ID>?v=<更新時刻>` のURLだけを載せ、画像はブラウザにキャッシュさせます。合言葉を設定している場合は画像の配信にも合言葉が必要で、非公開のマップは一覧にも画像にも出ません。

参加者側は最大320%まで拡大でき、拡大中は横スクロールで見たい場所へ移動できます。「この地図を印刷」で紙にも出せます。複数登録すると（校舎・屋外など）名前のタブで切り替わります。手順は管理者向けマニュアルの「会場マップの登録」にまとめています。

参加者向け画面はスマートフォン幅では縦1列、1024px以上では本文の横にレールが出る2カラム表示に切り替わります。下部ナビは「スタンプ帳」「設置場所」「読み取る」「マップ」「特典」の1行で、読み取るを2つずつのタブではさむことで画面の中央に置いています。狭い幅に合わせて下部バーだけ「マップ」と短く表示し、レールでは「フロアマップ」と出します。使い方・再ログイン・参加データはヘッダーの歯車（設定）にまとめています。表示テーマと言語はヘッダーに並べています。

## 報酬の受け取り

全スタンプを集めると、特典タブに「報酬を受け取る」が出ます。押すと「係員にこの画面を見せてください」という画面になり、**引き換え用のバーコード（Code128）・QRコード・番号**が表示されます。係員が管理画面の「景品引き換え」でそれを読み取ると、その場で照合して交換が記録され、参加者の画面は数秒で印付きの受け取り記録に切り替わります。参加者だけでは確定できません。以後は何度開いても同じ記録が出ます（再交換はできません）。

景品引き換えの欄はハンディスキャナ（キーボード入力型）でそのまま読み取れ、端末のカメラでQRコードを読むことも、番号を手入力することもできます。全角数字や空白が混じっても照合します。結果は「引き換えOK」「交換済み」「未コンプリート」「期限切れ」「読み取れない」のいずれかを色付きで大きく表示し、直前の読み取りも一覧に残ります。誤操作はその場で取り消せます。

コードは参加者の行IDと、そのIDと5分ごとの時間枠に対するHMAC由来の8桁で構成します（数字のみ・偶数桁なので Code128 C で短く収まります）。受け付けるのは現在と直前の枠だけなので、表示から5〜10分でスクリーンショットは使えなくなり、番号から他人のコードを作ることもできません。完了判定は読み取りの時点でサーバーが数え直します。バーコードでの記録は管理操作の履歴に `reward_scan` として、端末名とともに残ります。窓口の端末は、管理者が設定した**引き換え係のパスワード**でログインすれば景品引き換えだけを使えます。引き換え係の端末から取り消せるのは記録から10分以内だけです（取り消しと再読み取りで景品を二重に受け取る不正を防ぐため）。それより前の記録は管理者が参加者管理ダイアログから取り消します。

スキャナも管理画面も使えない窓口のために、係員が参加者の端末で暗証番号を入力して確定する方法も残しています（受け取り画面の「暗証番号で確定する（係員用）」）。暗証番号は管理画面の「設定」タブで6〜8桁の数字を登録します（以前に登録した4〜5桁の番号はそのまま使えますが、登録し直しを推奨します）。未設定のときはこの方法だけが使えず、バーコードでの引き換えは使えます。値はHMACでハッシュ化して保存し、参加者向けAPIの応答には一切含めません。参加者の端末で入力するものなので、他で使っていない番号にしてください。総当たり対策として、**全スポットを集め終えた参加者だけ**が入力でき、間違いは参加者の行IDごとに15分8回・接続元ごとに15分30回までです。行IDで数えるので、再ログインや参加証の作り直しで回数を増やすことはできません。

交換の状況は管理画面の参加者一覧に「報酬交換」列として出ます。統計カードに交換済み人数、CSVに交換有無・コンプリート日時・交換日時が入ります。参加者管理ダイアログからは、紙の台紙で参加した人などを手動で交換済みにしたり、誤操作を取り消したりできます。確定・取り消しは監査ログに残ります。

## 個別スタンプ編集と初回ガイド

管理画面の「参加者・進行状況」→「管理」→「スタンプ達成状況を編集」で、各地点のスタンプを付与・取り消せます。各操作で即時保存し、参加者のスタンプ帳と管理側の集計・ランキングに反映します（開いたままの参加者画面は再読み込みが必要です）。新規付与は現在時刻、獲得済みの再付与は元の有効な日時を保持します。非公開地点の記録も編集できますが、達成数には含みません。操作は参加者ID・場所IDとともに管理履歴へ記録します。

新規登録後、復旧コードの保存確認を終えると、3ステップの使い方デモを表示します。場所の一覧・QR読み取り・コンプリートを画面の模式図で説明します。デモではカメラや押印APIを使用しません。スキップ・戻る・再表示に対応し、日本語/英語と動きを減らす設定に追従します。再ログインや復旧コードの再発行時には自動表示しません。

設定シートの「使い方」には、デモの隣に `/help` の**使い方ガイド**へ進むボタンを置いています。4ステップの流れ、読み取りのコツ3点、よくある質問（読み取れない・カメラが起動しない・重複取得・登録とログイン・端末変更・混み具合・報酬の受け取り）を1ページにまとめた読み物で、質問は折りたたみです。ガイドは通信を行わず、この文化祭の設置場所など個別の情報も持ちません。下部ナビのない1カラムで、ヘッダーのテーマ・言語切り替えと日本語/英語はそのまま使えます。
